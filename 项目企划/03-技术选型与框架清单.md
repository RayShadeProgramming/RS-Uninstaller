# RS-Uninstaller 技术选型与框架清单

> 文档版本：v0.1（企划阶段）
> 日期：2026-10-13
> 说明：本文档只确定**技术方向与依赖清单**，不涉及具体编码。

---

## 1. 总体技术栈

| 层 | 选型 | 说明 |
| --- | --- | --- |
| 语言 | **Go** | 后端引擎与图形界面统一使用 Go |
| 目标平台 | Windows 10 / 11（x64） | 仅 Windows，可处理 x86 应用 |
| 架构 | 分层解耦：核心引擎（无 UI 依赖）+ 界面层 | 界面方案可替换，引擎可复用于 CLI |
| 构建 | 单文件绿色程序 | 目标是**全链路无 CGO**，便于打包与分发 |
| 权限 | UAC `requireAdministrator` | 处理系统目录与注册表 |

## 2. 图形界面（GUI）方案选型

由于本项目**仅面向 Windows**，且你希望"图形界面也用 Go 做"，下面是主流 Go GUI 方案对比：

| 方案 | 语言构成 | 渲染方式 | 外观 | 需要 CGO | 契合度 |
| --- | --- | --- | --- | --- | --- |
| **Walk**（`lxn/walk`） | **纯 Go** | 封装原生 Win32 控件 | Windows 原生 | ❌ 不需要 | ⭐⭐⭐⭐⭐ |
| Fyne | 纯 Go 代码 | 自绘（OpenGL） | 统一风格、非原生 | ✅ 需要 | ⭐⭐⭐⭐ |
| Wails v2 | Go + **Web 前端**（HTML/CSS/JS） | 系统 WebView2 | 现代、可高度定制 | ❌ 不需要 | ⭐⭐⭐⭐ |
| Gio | 纯 Go | 自绘 | 需自行设计 | ✅ 需要 | ⭐⭐⭐ |

### 推荐结论

> **首选：Walk（`github.com/lxn/walk`）**

理由：

1. **纯 Go 实现**，满足"图形界面也用 Go 做"的要求；
2. **不需要 CGO**，不依赖 C 编译器，可实现"一个 `go build` 出单文件 exe"的绿色分发；
3. **原生 Windows 控件外观**，与"Windows 专属工具"的定位一致，原生列表 / 树形 / 右键菜单体验好；
4. 本项目界面以**列表 + 详情 + 进度 + 确认对话框**为主，Walk 完全胜任，无需复杂动效。

**备选方案**：

- 若后期对 UI 美观度 / 主题化要求提高 → 可迁移到 **Wails**（Go 核心逻辑完全保留，仅重写 UI 层；但前端将使用 Web 技术，不再是纯 Go 前端）；
- 若希望保留未来跨平台可能 → **Fyne**（纯 Go 代码，但构建需 CGO 环境）。

> 关键设计约束：**核心引擎不得依赖任何 UI 包**。这样界面方案（Walk / Wails / Fyne）可随时替换，也能顺带产出 CLI 版本。

## 3. 所需 Go 框架与依赖库清单

### 3.1 Windows 系统交互（核心）

| 库 | 用途 |
| --- | --- |
| `golang.org/x/sys/windows` | Win32 API 调用（文件、进程、句柄、提权、互斥体） |
| `golang.org/x/sys/windows/registry` | 注册表读写（软件枚举、痕迹清理） |
| `golang.org/x/sys/windows/svc` 及 `svc/mgr` | 服务查询与停止/删除 |
| `github.com/lxn/walk` | 图形界面（原生 Windows 控件） |
| `github.com/lxn/win` | Walk 依赖的 Win32 封装与常量 |
| `github.com/go-ole/go-ole` | COM/OLE 调用（MSI API、Shell、WMI、计划任务） |

### 3.2 系统信息与查询

| 库 | 用途 |
| --- | --- |
| `github.com/yusufpapurcu/wmi` | 通过 WMI 查询服务、启动项、系统还原点等 |
| `github.com/shirou/gopsutil/v3` | 进程、磁盘、内存等系统信息 |
| `github.com/google/uuid` | 生成备份/会话唯一标识 |

> 系统还原点：通过 `SRSetRestorePointW`（`srclient.dll`）或 WMI `SystemRestore` 类实现。

### 3.3 数据存储与配置

| 库 | 用途 |
| --- | --- |
| `modernc.org/sqlite` | 纯 Go SQLite（**无需 CGO**），缓存软件清单、规则库、备份索引 |
| `github.com/spf13/viper` 或 `github.com/BurntSushi/toml` | 配置文件读写 |
| 标准库 `encoding/json` | 规则库 / 备份索引的序列化 |

### 3.4 日志、命令行与工具

| 库 | 用途 |
| --- | --- |
| `go.uber.org/zap` 或 `github.com/rs/zerolog` | 结构化日志（卸载过程留痕，便于排错与出报告） |
| `github.com/spf13/cobra` | CLI 子命令（阶段 0/1 的只读原型、调试用） |
| `github.com/stretchr/testify` | 单元测试断言 |
| 标准库 `archive/zip` | 备份打包 |

### 3.5 打包与资源嵌入

| 工具 / 库 | 用途 |
| --- | --- |
| `github.com/josephspurrier/goversioninfo` | 生成版本信息、图标、UAC manifest 资源 |
| `github.com/tc-hib/go-winres` | 另一种 Windows 资源（图标/manifest）嵌入方案 |
| `go build -ldflags "-H windowsgui -s -w"` | 隐藏控制台窗口、减小体积 |

### 3.6 提权与单实例

| 方案 | 用途 |
| --- | --- |
| UAC manifest `requireAdministrator` | 启动即申请管理员权限 |
| `ShellExecuteEx` + `runas` | 已运行时动态提权（备用） |
| `CreateMutex`（`x/sys/windows`） | 单实例运行控制 |

## 4. 建议的工程目录结构

```
RS-Uninstaller/
├── go.mod
├── README.md
├── 项目企划/                     # 本策划文档目录
├── cmd/
│   └── rsuninstaller/
│       └── main.go               # 程序入口（装配 UI 与引擎）
├── internal/
│   ├── scanner/                  # 软件扫描器（注册表 / UWP / MSI）
│   ├── trace/                    # 痕迹追踪器（文件 + 注册表）
│   ├── cleaner/                  # 清理引擎（含白名单校验）
│   ├── backup/                   # 备份与还原（还原点 / .reg / 隔离区）
│   ├── rule/                     # 软件指纹规则库与匹配
│   ├── privilege/                # 提权与权限检测
│   └── winapi/                   # Win32 / WinRT 调用封装
├── ui/                           # 图形界面层（Walk）
│   ├── views/                    # 列表页、详情页、进度页等
│   └── assets/                   # 图标等资源
├── pkg/                          # 可对外复用的公共包
├── rules/                        # 内置规则库数据文件
└── build/                        # 打包脚本、资源、manifest
```

**分层依赖方向（单向，禁止反向）**：

```
ui  →  cmd  →  internal/*  →  winapi
```

即：UI 可以调用引擎，引擎**不可以**依赖 UI。这是保证"界面可替换"的关键。

## 5. 关键依赖风险提示

| 依赖 | 风险 | 应对 |
| --- | --- | --- |
| `lxn/walk` | 维护活跃度一般 | 界面只做常规控件；如遇问题可迁移 Wails/Fyne |
| `modernc.org/sqlite` | 体积略大 | 备选：改用 JSON 文件存储 |
| COM / WMI 调用 | 易受系统环境影响 | 封装统一错误处理，失败时降级 |
| 系统还原点 API | 部分环境被组策略禁用 | 检测不可用时降级为"文件隔离区 + 注册表备份" |

---

## 6. 技术选型小结

- **语言**：Go（全链路，含界面）。
- **界面**：**Walk**（纯 Go、原生 Windows、无 CGO）；后备 Wails / Fyne。
- **核心依赖**：`golang.org/x/sys/windows` + `registry` + `svc`、`go-ole`、`wmi`、`walk`、`modernc.org/sqlite`。
- **构建目标**：无 CGO、单文件、可签名、管理员权限运行的 Windows 绿色程序。
