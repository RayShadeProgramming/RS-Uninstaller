# RS-Uninstaller 技术选型与框架清单

> 文档版本：v0.2（技术路线调整为 C++）
> 日期：2026-10-17
> 说明：本文档确定**技术方向、框架与依赖清单、构建方式**，不涉及具体编码。

---

## 1. 总体技术栈

| 层 | 选型 | 说明 |
| --- | --- | --- |
| 语言 | **C++20** | 业务逻辑与界面统一使用 C++ |
| 编译器 | **MinGW-w64 g++** | 本地已配置，直接可用 |
| 界面 | **纯 Win32 API + 公共控件** | 不使用 Qt 等需要附带运行时的框架 |
| 目标平台 | Windows 10 / 11（x64） | 仅 Windows，可处理 x86 应用 |
| 构建 | **CMake + Ninja**（或 Makefile） | 交叉可控，便于静态链接 |
| 产物 | **单个 `.exe`** | 静态链接，双击即用，无需安装 |
| 权限 | UAC `requireAdministrator` | 编译进 manifest |

---

## 2. 硬性约束

以下约束优先级最高，任何选型不得违反：

| 编号 | 约束 | 判定方式 |
| --- | --- | --- |
| C1 | 最终交付**只有一个 exe** | 交付目录中无其他必需文件 |
| C2 | **不依赖外部运行时** | `objdump -p` 检查依赖，仅系统 DLL |
| C3 | **不用 Qt / Sciter / WebView2 等** | 不引入需要 DLL、插件或系统组件的 UI 框架 |
| C4 | **原生 Windows 外观** | 使用系统公共控件 |
| C5 | 可用 MinGW g++ 编译 | 本地工具链直接构建 |

> 判断标准很简单：**把 exe 拷到一台只装了 Windows 的干净机器上，双击能跑，就算达标。**

## 3. 界面方案选型

| 方案 | 产物形态 | 运行时依赖 | 外观 | MinGW 兼容 | 结论 |
| --- | --- | --- | --- | --- | --- |
| **纯 Win32 + Common Controls** | 单 exe | 仅系统 DLL | Windows 原生 | ✅ 完善 | ⭐ **首选** |
| WTL（header-only 封装） | 单 exe | 无 | 原生 | ⚠️ 部分特性依赖 MSVC | 可选（不建议初期引入） |
| Dear ImGui | 单 exe（静态） | 系统 D3D11 / OpenGL | 自绘、工具风 | ✅ 可用 | 备选 |
| FLTK | 单 exe（静态） | 无 | 自绘、偏旧 | ✅ 可用 | 备选 |
| wxWidgets | 可静态但构建复杂 | 无（需静态配置） | 原生近似 | ⚠️ 配置繁琐 | 不推荐 |
| **Qt** | 需 Qt DLL / 插件，或庞大静态构建 | Qt 运行时 | 原生近似 | ⚠️ | ❌ **排除（明确不用）** |
| WebView2 | exe + 依赖 Edge WebView2 Runtime | 系统组件，可能缺失 | Web | ⚠️ | ❌ 不满足 C1/C2 |
| Sciter | 需 DLL / 商业授权 | 商业运行时 | Web | — | ❌ 排除 |

### 推荐结论

> **采用：纯 Win32 API + 公共控件（`comctl32`）**

理由：

1. **零第三方依赖**：Win32 API 与公共控件是 Windows 自带组件，永远存在；
2. **真正的单文件**：静态链接后产物就是一个 exe，不需要任何 DLL、插件或运行时；
3. **原生外观与手感**：`ListView` / `TreeView` / `TaskDialog` 都是系统控件，配合 comctl32 v6 清单即有现代视觉样式；
4. **体积小、启动快**：无框架初始化开销，适合工具类软件；
5. **MinGW 支持完善**：头文件与库齐全，`windres` 处理资源无压力。

**为什么不用 Qt**：Qt 程序要么附带一堆 Qt DLL，要么做全静态构建（体积大、插件与授权问题多），都不满足"单文件、零依赖"的要求。

**备选方案**：若后期需要更复杂的自绘界面，可考虑 **Dear ImGui**（可静态编译进 exe），但外观会偏"工具风"，与原生体验有差距。

### 界面元素与控件映射

| 界面元素 | 控件 | 关键样式 / 说明 |
| --- | --- | --- |
| 软件列表 | `ListView` | `LVS_REPORT` + `LVS_EX_CHECKBOXES` / `LVS_EX_FULLROWSELECT` |
| 搜索框 | `Edit` | 配合 `EM_SETCUEBANNER` 显示占位提示 |
| 清理清单 | `TreeView` | `TVS_HASBUTTONS` + `TVS_CHECKBOXES`，按类别分组 |
| 进度 | `ProgressBar` | `PBM_SETMARQUEE` 用于不确定进度 |
| 日志 / 详情 | `Edit`（多行只读）或 `RichEdit` | 便于复制 |
| 风险确认 | `TaskDialog` | 比 `MessageBox` 更清晰，支持自定义按钮 |
| 菜单 / 工具栏 | `Menu` / `Toolbar` | 原生 |
| 状态栏 | `StatusBar` | 显示计数与进度 |

## 4. 依赖库清单

设计原则：**只选「头文件」或「可源码编译」的库**，杜绝二进制 DLL 依赖。

### 4.1 系统 API（无需分发）

| 组件 | 链接库 | 用途 |
| --- | --- | --- |
| Win32 基础 | `kernel32` / `user32` / `gdi32` | 窗口、消息、文件、进程 |
| 公共控件 | `comctl32` | ListView / TreeView / ProgressBar / TaskDialog |
| 注册表 | `advapi32` | `Reg*` 系列 API |
| Shell | `shell32` / `shlwapi` | 路径处理、快捷方式、回收站、文件操作 |
| 服务管理 | `advapi32`（SCM） | `OpenSCManager` / `EnumServicesStatusEx` / `DeleteService` |
| MSI 枚举 | `msi` | `MsiEnumProductsExW` |
| 系统还原点 | 动态加载 `srclient.dll` | `SRSetRestorePointW`，避免链接期依赖 |
| 加密 / 哈希 | `bcrypt` | 校验、备份索引校验 |
| 网络（可选） | `winhttp` | 规则库更新，系统自带，无需 OpenSSL |
| 版本信息 | `version` | 读取 exe 版本 |

> **COM 使用原则**：能用直接 API 就不用 COM。MinGW 对 `comdef.h` / `__uuidof` 支持不完整，所有 GUID 一律显式引用 `IID_*` / `CLSID_*`。

### 4.2 第三方库（源码 / 头文件形式）

| 库 | 形式 | 用途 | 说明 |
| --- | --- | --- | --- |
| **SQLite**（amalgamation） | `sqlite3.c` + `sqlite3.h` | 本地数据库：软件清单缓存、规则库、备份索引 | 直接编译进 exe |
| **nlohmann/json** | 单头文件 | 规则库、配置文件、报告序列化 | 免链接 |
| **spdlog** | header-only 模式 | 结构化日志 | 也可换 `plog` |
| **miniz** | 单 `.c` / `.h` | ZIP 压缩，用于备份打包 | 极轻量 |
| **Catch2** | header-only（v2） | 单元测试 | 仅测试用，不进发布产物 |
| 标准库 | C++20 | `std::filesystem`、`std::string`、`std::thread` | 文件遍历与并发 |

> **刻意不引入**：Boost（体积大、编译慢）、任何 GUI 框架、任何需要 `.dll` 的库。

### 4.3 构建与工具

| 工具 | 用途 |
| --- | --- |
| **MinGW-w64 g++** | 编译（本地已就绪） |
| **windres** | 编译 `.rc` 资源（图标、版本、manifest） |
| **CMake ≥ 3.20 + Ninja** | 构建管理（推荐）；也可直接用 Makefile |
| **objdump** | 检查 exe 依赖的 DLL |
| **strip**（`-s`） | 去除符号，减小体积 |
| **signtool**（外部） | 发布前代码签名 |

### 分层依赖方向（单向，禁止反向）

```
ui  →  app  →  core  →  platform
```

- `core` **不得**包含任何 `#include <windows.h>` 之外的 UI 头文件；
- 所有 Win32 调用集中在 `platform`，便于测试与替换；
- `ui` 只负责展示与交互，不写业务逻辑。

## 6. 构建与单文件打包

### 6.1 CMakeLists 关键配置

```cmake
cmake_minimum_required(VERSION 3.20)
project(RS-Uninstaller LANGUAGES C CXX)

set(CMAKE_CXX_STANDARD 20)
set(CMAKE_CXX_STANDARD_REQUIRED ON)
set(CMAKE_CXX_EXTENSIONS OFF)

add_executable(RS-Uninstaller WIN32
    src/main.cpp
    src/app/application.cpp
    src/core/scanner/scanner.cpp
    src/core/trace/tracer.cpp
    src/core/cleaner/cleaner.cpp
    src/core/backup/backup.cpp
    src/core/rule/rule.cpp
    src/platform/registry.cpp
    src/platform/service.cpp
    src/platform/filesystem.cpp
    src/platform/shell.cpp
    src/platform/restore_point.cpp
    src/platform/process.cpp
    src/ui/main_window.cpp
    src/ui/software_list_view.cpp
    src/ui/clean_preview_view.cpp
    src/ui/progress_dialog.cpp
    third_party/sqlite/sqlite3.c
    res/app.rc
)

target_include_directories(RS-Uninstaller PRIVATE include third_party)

target_compile_definitions(RS-Uninstaller PRIVATE
    UNICODE _UNICODE WIN32_LEAN_AND_MEAN NOMINMAX
)

target_compile_options(RS-Uninstaller PRIVATE -O2 -Wall -Wextra)

target_link_options(RS-Uninstaller PRIVATE
    -municode -mwindows
    -static -static-libgcc -static-libstdc++
    -s
)

target_link_libraries(RS-Uninstaller PRIVATE
    comctl32 shlwapi shell32 advapi32
    ole32 oleaut32 uuid
    msi winhttp bcrypt version
    gdi32 user32 comdlg32 setupapi
)
```

### 6.2 等价的手工命令（不使用 CMake 时）

```bash
# 1) 编译资源
windres res/app.rc -O coff --codepage=65001 -o build/app.res

# 2) 编译并静态链接
g++ -std=c++20 -O2 -DUNICODE -D_UNICODE -DWIN32_LEAN_AND_MEAN -DNOMINMAX \
    -Iinclude -Ithird_party \
    src/main.cpp src/app/*.cpp src/core/*/*.cpp src/platform/*.cpp src/ui/*.cpp \
    third_party/sqlite/sqlite3.c build/app.res \
    -municode -mwindows -static -static-libgcc -static-libstdc++ -s \
    -lcomctl32 -lshlwapi -lshell32 -ladvapi32 -lole32 -loleaut32 -luuid \
    -lmsi -lwinhttp -lbcrypt -lversion -lgdi32 -luser32 -lcomdlg32 -lsetupapi \
    -o build/RS-Uninstaller.exe
```

**关键参数说明：**

| 参数 | 作用 |
| --- | --- |
| `-municode` | 使用 `wWinMain` 入口，支持 Unicode |
| `-mwindows` | GUI 子系统，不弹控制台窗口 |
| `-static` | 静态链接所有库（含 winpthread） |
| `-static-libgcc` / `-static-libstdc++` | 不依赖 `libgcc` / `libstdc++` DLL |
| `-s` | 去除符号表，减小体积 |
| `--codepage=65001` | windres 用 UTF-8 读取资源，避免中文乱码 |

### 6.3 资源文件要点

`.rc` 中需包含：

```
1        ICON    "icon.ico"
1        VERSIONINFO ...
1        24      "app.manifest"     // 24 = RT_MANIFEST
```

`app.manifest` 必须声明三件事：

```xml
<!-- 1. 管理员权限 -->
<requestedExecutionLevel level="requireAdministrator" uiAccess="false"/>

<!-- 2. 公共控件 v6（现代视觉样式） -->
<dependency>
  <dependentAssembly>
    <assemblyIdentity type="win32"
        name="Microsoft.Windows.Common-Controls"
        version="6.0.0.0"
        processorArchitecture="*"
        publicKeyToken="6595b64144ccf1df"
        language="*"/>
  </dependentAssembly>
</dependency>

<!-- 3. 高 DPI 感知 -->
<dpiAware xmlns="http://schemas.microsoft.com/SMI/2005/WindowsSettings">true/pm</dpiAware>
<dpiAwareness xmlns="http://schemas.microsoft.com/SMI/2016/WindowsSettings">permonitorv2</dpiAwareness>
```

## 7. 单文件 exe 校验清单

构建完成后必须逐项确认：

| 检查项 | 方法 | 通过标准 |
| --- | --- | --- |
| 依赖的 DLL | `objdump -p build/RS-Uninstaller.exe \| grep "DLL Name"` | 仅系统 DLL（kernel32、user32、comctl32、advapi32 等） |
| MinGW 运行时 | 同上，搜索 `libstdc++` / `libgcc` / `libwinpthread` | **无输出** |
| 资源是否嵌入 | 资源查看器 / `windres` 反向检查 | 有图标、版本信息、manifest |
| 干净机器验证 | 拷贝到未装 MinGW 的 Windows | 双击正常运行 |
| 体积 | 文件属性 | 控制在数 MB 内（目标 1~3 MB） |
| 中文显示 | 界面与资源字符串 | 无乱码 |

> 只要"干净机器双击能跑"，单文件目标即达成。

## 8. 风险与注意事项

| 风险 | 说明 | 应对 |
| --- | --- | --- |
| MinGW 的 COM / WMI 支持弱 | `comdef.h` 缺失、`__uuidof` 不完整 | 回避 WMI；GUID 显式声明 |
| 静态链接体积偏大 | libstdc++ 静态链接会增加体积 | `-Os` / `-O2` + `-s`，按需裁剪 |
| 中文资源乱码 | `.rc` 编码与 windres 代码页不一致 | `--codepage=65001`，源文件统一 UTF-8 |
| 杀软误报 | 强制卸载类工具 + 静态体积异常，易被误判 | 代码签名、提交白名单、**不要用 UPX 加壳** |
| `-municode` 链接报错 | 入口函数名不匹配 | 入口使用 `wWinMain`，并确保加 `-municode` |
| C++ 异常跨越 Win32 回调 | 异常逃出窗口过程会导致崩溃 | 在窗口过程边界统一 `try/catch` |
| 第三方库许可证 | SQLite（公有领域）、spdlog（MIT）、nlohmann/json（MIT） | 均为宽松许可，保留声明即可 |

## 9. 技术选型小结

- **语言**：C++20。
- **编译器**：本地已配置的 MinGW-w64 `g++`。
- **界面**：**纯 Win32 API + 公共控件**，不用 Qt，不用任何需要 DLL 的框架。
- **核心依赖**：SQLite（源码）、nlohmann/json（头文件）、spdlog（头文件）、miniz（源码）。
- **构建**：CMake + Ninja，全静态链接，`windres` 嵌入资源。
- **产物**：**单个 `RS-Uninstaller.exe`**，无安装、无运行时依赖、原生界面。
