# RS-Uninstaller 开发周期与阶段规划

> 文档版本：v0.2（技术路线调整为 C++）
> 日期：2026-10-17
> 说明：本规划只做**阶段划分**，不细化到人天排期。每阶段给出目标、交付物与验收标准。

---

## 总体路线

```
阶段0 工具链验证 + 只读原型
        ↓
阶段1 核心引擎（扫描 + 追踪）
        ↓
阶段2 安全兜底（还原点 / 备份 / 白名单）
        ↓
阶段3 原生界面（Win32）
        ↓
阶段4 功能完善 + 规则库
        ↓
阶段5 单文件打包 / 签名 / 发布
```

**设计原则：**
1. **先验证打包，再写业务** —— 阶段 0 必须先确认"能产出单文件无依赖 exe"；
2. **先只读，再删除** —— 只扫描不删除，把识别准确率做扎实；
3. **先安全，再动手** —— 备份 / 还原必须先于删除能力上线；
4. **小步验收** —— 每个阶段以可运行、可验收的产物结束。

---

## 阶段 0：工具链验证与只读原型

**目标**：确认 MinGW 工具链能产出**单个无依赖 exe**，并跑通"软件枚举 + 清理清单生成"的只读原型。

- **内容**
  - 验证本地 `g++`、`windres`、`cmake` 可用性，锁定版本；
  - 编译一个最小 Win32 窗口程序（含 ListView、`.rc` 图标、UAC manifest），确认静态链接后**无 MinGW 运行时 DLL**；
  - 打通三类软件来源：机器级注册表（64/32 位）、用户级注册表、MSI 产品库；
  - 解析卸载项字段，实现系统组件 / 补丁过滤；
  - 给定一款软件，生成"可能的清理清单"（文件 + 注册表），**仅展示不删除**。
- **交付物**
  - 工具链验证报告（含 `objdump` 依赖检查结果）；
  - 命令行只读原型（控制台版，便于快速验证）；
  - 识别准确率记录。
- **验收标准**
  - 产出的 exe 依赖列表中**只有 Windows 系统 DLL**，无 `libstdc++` / `libgcc` / `libwinpthread`；
  - 能正确列出本机 ≥ 95% 的常规已安装软件；
  - 清理清单对典型软件的主要目录与注册表项命中。

---

## 阶段 1：核心引擎（扫描 + 追踪）

**目标**：完成"软件扫描器"与"痕迹追踪器"，形成完整、结构化的清理清单。

- **内容**
  - 软件扫描器：多源合并、去重、过滤，输出统一软件模型；
  - 痕迹追踪器：按 `InstallLocation` / 厂商名 / 产品名，追踪文件与注册表痕迹；
  - 覆盖：安装目录、AppData / ProgramData、开始菜单快捷方式、卸载键、厂商注册表项；
  - 引擎与界面**完全解耦**（纯 C++ 库，不依赖任何 UI 代码）。
- **交付物**：可复用的核心引擎静态库 / 源码模块 + 控制台调试工具。
- **验收标准**：对典型软件输出的清理清单人工抽查准确率 ≥ 90%；误报可控。

---

## 阶段 2：安全兜底机制

**目标**：建立"出事能还原"的安全底座。**本阶段必须早于实际删除能力上线。**

- **内容**
  - 系统还原点：动态加载 `srclient.dll`，调用 `SRSetRestorePointW`；
  - 注册表备份 / 恢复：导出 `.reg` 与回灌；
  - 文件"隔离区"：删除前移动到隔离区，保留目录结构，支持一键还原；
  - 保护白名单：系统关键目录、共享运行库、.NET / VC++ 组件；
  - 删除失败处理：被占用文件使用 `MoveFileEx` 安排重启后删除。
- **交付物**：备份与还原模块 + 还原验证报告。
- **验收标准**：能完成"备份 → 删除 → 从备份 100% 还原"的闭环测试；白名单可有效拦截对系统目录的删除请求。

---

## 阶段 3：原生界面（Win32）

**目标**：产出可交互的桌面客户端，把核心能力包装成普通用户可用的产品。

- **内容**
  - 主窗口框架（菜单、工具栏、状态栏、DPI 适配）；
  - 软件列表（`ListView` 报表模式，多列、排序、复选、图标）；
  - 搜索与筛选；
  - 清理清单预览（`TreeView` 复选，按文件 / 注册表 / 服务分组）；
  - 卸载执行页（`ProgressBar` + 日志区 + 结果报告）；
  - 备份 / 还原入口与"隔离区"管理；
  - 原生对话框（`TaskDialog`）做风险确认。
- **交付物**：Win32 图形界面客户端。
- **验收标准**：完整跑通"选择软件 → 预览清单 → 备份 → 卸载 → 报告 → 还原"全流程。

---

## 阶段 4：功能完善与规则库

**目标**：提升"卸得干净"的能力与覆盖面。

- **内容**
  - 服务清理（SCM API：停止 / 删除）；
  - 计划任务清理；
  - 开机启动项清理（注册表 `Run` / `RunOnce`、启动文件夹）；
  - 文件关联、右键菜单、COM 注册、Shell 扩展清理；
  - 内置软件指纹规则库（可增量更新）；
  - 批量卸载、卸载报告导出。
- **交付物**：功能完整版客户端 + 规则库文件。
- **验收标准**：覆盖更多软件类型；常见软件的残留项检出率明显提升。

---

## 阶段 5：单文件打包、签名与发布

**目标**：打磨稳定性、确保"单 exe 零依赖"，通过安全软件与系统信任校验，正式交付。

- **内容**
  - 全量静态链接检查：`-static -static-libgcc -static-libstdc++`，`objdump -p` 复核依赖；
  - 编译优化与裁剪：`-O2` / `-Os`、`-s`、剔除未使用模块；
  - 资源完善：图标、版本信息、UAC manifest、comctl32 v6 清单、DPI 声明；
  - 多版本 Windows（10 / 11）与多软件矩阵测试；
  - 高风险场景专项测试（系统组件保护、误删回滚）；
  - 代码签名（消除 SmartScreen 警告）+ 杀软误报申诉；
  - 发布包：仅一个 `.exe`（可附校验值）。
- **交付物**：签名的单文件发布版 + 用户手册 + 风险提示。
- **验收标准**：exe 双击即用、无需安装；依赖仅系统 DLL；无高危误删缺陷；主流杀软无误报。

## 里程碑一览

| 里程碑 | 对应阶段 | 关键成果 |
| --- | --- | --- |
| M0 工具链与原型验证 | 阶段 0 | 单文件 exe 验证通过 + 只读原型 |
| M1 引擎可用 | 阶段 1 | 扫描 + 追踪引擎 |
| M2 安全底座就绪 | 阶段 2 | 备份还原闭环 |
| M3 客户端跑通 | 阶段 3 | Win32 界面完整流程 |
| M4 功能完整 | 阶段 4 | 规则库 + 高级清理 |
| M5 正式发布 | 阶段 5 | 签名单文件交付 |

---

## 阶段依赖关系

- 阶段 0 的**打包验证**是后续所有阶段的前提：若静态链接方案不成立，需在阶段 0 调整技术方案，不得带入后续阶段。
- 阶段 2 必须先于阶段 3 的"实际删除"功能完成；阶段 3 可以先做界面骨架，但删除按钮在阶段 2 验收前保持禁用。
- 阶段 4 依赖阶段 1 的引擎接口，新增清理能力应通过扩展引擎实现，不在界面层写业务逻辑。
