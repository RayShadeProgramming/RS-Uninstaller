# RS-Uninstaller 开发周期与阶段规划

> 文档版本：v0.3（技术路线调整为 Python）
> 日期：2026-10-17
> 说明：只做阶段划分，不细化到人天排期。每阶段给出目标、交付物与验收标准。

---

## 总体路线

```
阶段0 环境验证 + 只读原型
        ↓
阶段1 核心引擎（扫描 + 追踪）
        ↓
阶段2 安全兜底（还原点 / 备份 / 白名单）
        ↓
阶段3 tkinter 界面
        ↓
阶段4 功能完善 + 规则库
        ↓
阶段5 单文件打包 / 签名 / 发布
```

**设计原则：**
1. **先只读，再删除** —— 只扫描不删除，把识别准确率做扎实；
2. **先安全，再动手** —— 备份 / 还原必须先于删除能力上线；
3. **先跑通，再打包** —— 开发阶段用 `python run.py` 调试，功能稳定后再打 exe；
4. **小步验收** —— 每个阶段以可运行、可验收的产物结束。

---

## 阶段 0：环境验证与只读原型

**目标**：确认 Python 环境与标准库能力，跑通"软件枚举 + 清理清单生成"的只读原型。

- **内容**
  - 确认 Python 3.10+ 可用，`tkinter` 可正常导入（Windows 官方安装包默认自带）；
  - 实现注册表扫描：机器级（64 / 32 位视图）、用户级；
  - 实现卸载项字段解析与系统组件 / 补丁过滤；
  - 给定一款软件，生成可能的清理清单（文件 + 注册表），**仅展示不删除**。
- **交付物**：可运行的控制台脚本（或界面雏形）+ 识别准确率记录。
- **验收标准**：能列出本机 ≥ 95% 的常规已安装软件；典型软件的安装目录与卸载键被正确识别。

---

## 阶段 1：核心引擎（扫描 + 追踪）

**目标**：完成扫描器与追踪器，形成结构化清理清单。

- **内容**
  - 多源合并、去重、过滤，输出统一软件模型；
  - 按 `InstallLocation`、厂商名、产品名追踪文件与注册表痕迹；
  - 覆盖：安装目录、AppData / ProgramData、开始菜单、桌面快捷方式、卸载键、厂商注册表项。
- **交付物**：`scanner.py` + `trace.py` 可独立调用。
- **验收标准**：典型软件清单人工抽查准确率 ≥ 90%，误报可控。

---

## 阶段 2：安全兜底机制

**目标**：建立"出事能还原"的安全底座。**必须早于删除能力上线。**

- **内容**
  - 系统还原点创建（`srclient.dll`）；
  - 注册表递归快照与回灌；
  - 文件隔离区：删除前移动到隔离区并记录 journal；
  - 还原：文件回迁 + 注册表回灌，目录已存在时合并；
  - 保护白名单：系统盘根、Windows、Program Files、ProgramData、用户目录。
- **交付物**：`backup.py` + 还原验证记录。
- **验收标准**：完成"备份 → 删除 → 100% 还原"闭环；白名单可拦截对系统目录的删除。

---

## 阶段 3：tkinter 界面

**目标**：产出可交互的桌面客户端。

- **内容**
  - 主窗口：软件列表（`ttk.Treeview`）、搜索、排序、状态栏；
  - 清理预览窗口：勾选清单、还原点选项、风险确认；
  - 执行进度：后台线程 + 进度条 + 结果报告；
  - 隔离区窗口：会话列表、打开目录、一键还原；
  - 高 DPI 适配与系统主题。
- **交付物**：可完整操作的桌面程序。
- **验收标准**：完整跑通"选择软件 → 预览 → 备份 → 清理 → 报告 → 还原"，界面无卡死。

---

## 阶段 4：功能完善与规则库

**目标**：提升"卸得干净"的覆盖度。

- **内容**
  - 服务清理（SCM API）；
  - 计划任务、开机启动项清理；
  - 文件关联、右键菜单、COM 注册、Shell 扩展清理；
  - 内置软件指纹规则库（本地 JSON）；
  - 批量卸载、报告导出。
- **交付物**：功能完整版 + 规则库文件。
- **验收标准**：覆盖更多软件类型，常见软件残留检出率明显提升。

---

## 阶段 5：单文件打包、签名与发布

**目标**：打包为单个 exe，通过系统与安全软件信任校验。

- **内容**
  - PyInstaller `--onefile --windowed --uac-admin --icon` 打包；
  - 在**未安装 Python** 的干净 Windows 上验证；
  - 多版本 Windows（10 / 11）与多软件矩阵测试；
  - 高风险场景专项测试（系统组件保护、误删回滚）；
  - 代码签名 + 杀软误报申诉；
  - 发布包：仅一个 exe（附校验值）。
- **交付物**：签名的单文件发布版 + 用户手册。
- **验收标准**：干净机器双击即用；无需 Python；主流杀软无误报。

## 里程碑一览

| 里程碑 | 对应阶段 | 关键成果 |
| --- | --- | --- |
| M0 只读原型 | 阶段 0 | 扫描 + 清单生成，不删除 |
| M1 引擎可用 | 阶段 1 | 扫描器 + 追踪器 |
| M2 安全底座就绪 | 阶段 2 | 备份还原闭环 |
| M3 客户端跑通 | 阶段 3 | tkinter 完整流程 |
| M4 功能完整 | 阶段 4 | 规则库 + 高级清理 |
| M5 正式发布 | 阶段 5 | 单文件签名版 |

---

## 阶段依赖关系

- 阶段 2 必须先于阶段 3 中的"实际删除"功能完成；阶段 3 可先搭界面，删除按钮在阶段 2 验收前保持禁用。
- 阶段 4 的新增清理能力应扩展在 `trace.py` / `cleaner.py`，不在界面层写业务逻辑。
- 阶段 5 的打包验证若失败（体积、权限、杀软），需回到对应阶段修正，不带着问题发布。
