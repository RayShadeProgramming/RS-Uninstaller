## 1. 项目概述

### 1.1 项目名称
**RS-Uninstaller**

### 1.2 一句话定位
一款**仅面向 Windows 客户端**的深度强制卸载工具：自动识别本机已安装的全部软件，在**不启动软件自带卸载程序**的前提下，直接定位其安装目录、用户数据与注册表项，一次性彻底清除。

### 1.3 目标用户
- 反感"卸载要付费 / 弹广告 / 引导下载其他软件"的普通用户；
- 需要批量、干净卸载的装机 / 运维 / 电脑维护人员；
- 对系统残留、开机启动项敏感的性能爱好者。

### 1.4 与主流工具的差异

| 维度 | Geek Uninstaller | RS-Uninstaller |
| --- | --- | --- |
| 卸载方式 | 先调用**官方卸载程序**，成功后再扫描残留 | **不调用**官方卸载程序，直接清理 |
| 面对"收费卸载" | 无解，仍会被卸载程序拦截 | 直接跳过卸载程序，规避收费 / 广告关卡 |
| 残留清理 | 事后启发式扫描 | 事前构建"清理清单"（文件 + 注册表 + 服务 + 计划任务）后整体清除 |
| 安全模型 | 依赖官方卸载，风险天然较低 | 风险高，**必须**内置还原点 + 备份兜底 |
| 产品调性 | 通用卸载器 | 强制卸载 / 深度清理 |

> 结论：本项目与 Geek 的**根本区别**在于"跳过官方卸载程序"，这既是它的卖点，也是它最大的风险来源。整个技术方案必须围绕"如何安全地跳过"来设计。

| 编号 | 约束 | 说明 |
| --- | --- | --- |

- ❌ **不做任何破解 / 绕过授权**：本工具"跳过卸载程序"是为了规避卸载时的收费骚扰，**不是**为了破解软件、绕过正版验证。
- ❌ 不做跨平台（仅 Windows 客户端）。
- ❌ 不做软件管理 / 安装 / 更新（只做卸载）。
- ❌ 不做云同步、账号体系等外围功能。

## 3. 技术路线说明

### 3.1 从 Go 调整为 C++ 的原因

| 维度 | Go 方案（原） | C++ 方案（现） |
| --- | --- | --- |
| 单文件 exe | 可行 | 可行，且更彻底 |
| 运行时依赖 | 静态编译后可无 | 静态链接后可无 |
| 体积 | 偏大（数 MB 起） | 更小（纯 Win32 可控制在 1~3 MB） |
| 启动速度 | 快 | 更快（无 GC、无运行时初始化） |
| 系统 API 贴合度 | 需 cgo 或 syscall 封装 | **直接调用 Win32 API**，零中间层 |
| 界面方案 | Walk / Fyne / Wails | **纯 Win32 原生控件** |
| 工具链 | Go toolchain | **MinGW-w64 g++（本地已就绪）** |

**结论**：C++ + 纯 Win32 是本项目"单文件、无依赖、原生界面"约束下最直接的方案。系统调用无需跨语言桥接，打包链路最短。

### 3.2 单文件 exe 的实现路径

```
C++ 源码
  ├─ Win32 API（系统 DLL，无需分发）
  ├─ 第三方库（头文件 / 源码形式，直接编译进 exe）
  ├─ SQLite amalgamation（sqlite3.c 直接编译）
  ├─ 资源文件（.rc → windres → 嵌入 exe）
  └─ 静态链接 libstdc++ / libgcc / winpthread
        ↓
   单个 RS-Uninstaller.exe
```

关键点：
- 所有第三方库以**源码或头文件**形式引入，不引入 DLL；
- MinGW 运行时（`libstdc++-6.dll`、`libgcc_s_seh-1.dll`、`libwinpthread-1.dll`）通过 `-static` 系列参数静态链接；
- 图标、版本信息、UAC manifest 通过 `.rc` 资源编译进 exe；
- 配置与规则库内置默认值，首次运行按需释放到用户目录。

## 4. 技术可行性分析

### 4.1 软件信息来源（可行 ✅）

Windows 上软件的安装信息是**公开可枚举**的，主要有以下几类来源：

| 来源 | 位置 / 接口 | 覆盖范围 |
| --- | --- | --- |
| 64 位机器级注册表 | `HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Uninstall` | 常规 64 位软件 |
| 32 位机器级注册表 | `HKLM\SOFTWARE\WOW6432Node\...\Uninstall` | 32 位软件 |
| 当前用户级注册表 | `HKCU\SOFTWARE\Microsoft\Windows\CurrentVersion\Uninstall` | 仅当前用户安装的软件 |
| UWP / Store 应用 | `AppxPackage` 存储库（WinRT / `PackageManager`） | 微软商店应用 |
| MSI 产品库 | `MsiEnumProductsExW` / `MsiGetProductInfoW`（`msi.h`） | MSI 安装包软件 |
| 目录启发式扫描 | 遍历 `Program Files` / `Program Files (x86)` | 绿色 / 便携软件（补充手段） |

**注册表卸载项的关键字段**（用于识别与追踪）：

```
DisplayName / DisplayVersion / Publisher      # 名称、版本、厂商
InstallLocation                                # 安装目录（清理的起点）
UninstallString / QuietUninstallString         # 官方卸载命令（本项目不使用，仅参考）
DisplayIcon                                    # 图标（常指向安装目录）
EstimatedSize / InstallDate                    # 体积、安装日期
WindowsInstaller                               # 是否为 MSI 安装
SystemComponent / ParentKeyName / ReleaseType  # 用于过滤系统组件与补丁
```

**过滤规则**：需排除 `SystemComponent=1`（系统组件）、带 `ParentKeyName`（补丁 / 子组件）、`ReleaseType` 为 Update/Hotfix/Security Update 的条目，避免把系统补丁当软件列出。

对应 C++ API：`RegOpenKeyExW` / `RegEnumKeyExW` / `RegQueryValueExW` / `RegEnumValueW`，并按需指定 `KEY_WOW64_64KEY` 或 `KEY_WOW64_32KEY` 访问不同视图。

### 4.2 痕迹追踪可行性（部分可行 ⚠️）

"卸载干净"的本质是**判断哪些文件 / 注册表属于目标软件**。可行手段按可靠度排序：

| 可靠度 | 手段 | 说明 |
| --- | --- | --- |
| 高 | `InstallLocation` 递归 | 注册表直接给出的安装目录，最可靠 |
| 高 | 卸载键关联的注册表子键 | 厂商 / 产品名对应的 `HKCU\Software\<厂商>` 等 |
| 中 | 按名称 / 厂商匹配 | 匹配 AppData、ProgramData、开始菜单、Common Files 下的同名目录 |
| 中 | 服务 / 计划任务 / 启动项反查 | 通过服务的 `ImagePath` 反查程序目录 |
| 中 | 图标 / 快捷方式反查 | 快捷方式（`.lnk`）指向的路径 |
| 低 | COM / 文件关联 / Shell 扩展 | 需解析 CLSID 与源程序路径的对应关系 |
| 低 | 运行时行为追踪 | 监控安装 / 运行过程的写入点（本项目暂不做，留作远期） |

> **关键结论**：无法 100% 穷举某个软件的全部痕迹（这是所有卸载工具的共性局限）。因此产品不能承诺"绝对干净"，只能承诺"**在规则 + 追踪能力范围内尽量干净，且提供预览与回滚**"。这决定了产品必须走"**扫描 → 预览 → 备份 → 清理**"的安全流程，而不是"一键盲删"。

### 4.3 权限与提权（可行 ✅）

- 通过 UAC manifest 声明 `requireAdministrator`，编译进 exe 资源，启动即提权；
- 64 位进程访问注册表需区分 `KEY_WOW64_64KEY` / `KEY_WOW64_32KEY`；
- 系统还原点、服务管理、驱动目录操作均需管理员权限，已在设计内。

### 4.4 安全兜底可行性（可行 ✅）

| 兜底手段 | 实现方式 |
| --- | --- |
| 系统还原点 | 动态加载 `srclient.dll`，调用 `SRSetRestorePointW` |
| 注册表备份 | 导出为 `.reg`（等价于 `reg export`），支持 `.reg` 回灌 |
| 文件备份 | 删除前移动到"隔离区"（保留目录结构），支持一键还原 |
| 删除策略 | 优先"移动到隔离区 / 回收站"，而非直接不可恢复删除 |
| 白名单保护 | 内置系统关键目录、共享运行库、.NET / VC++ 组件保护名单 |

### 4.5 纯 Win32 界面可行性（可行 ✅）

本项目界面形态相对简单，属于典型的"原生工具类"界面：

| 界面元素 | Win32 实现 | 说明 |
| --- | --- | --- |
| 软件列表 | `ListView`（`LVS_REPORT`） | 支持多列、排序、复选、图标 |
| 搜索 / 筛选 | `Edit` + 筛选逻辑 | 标准输入框 |
| 详情面板 | `Static` / `Tab` / 自绘 | 展示软件信息 |
| 清理清单树 | `TreeView` + 复选 | 按"文件 / 注册表 / 服务"分组 |
| 进度显示 | `ProgressBar` | 标准进度条 |
| 确认 / 提示 | `TaskDialog` / `MessageBox` | 系统原生对话框 |
| 菜单 / 工具栏 | `Menu` / `Toolbar` / `Rebar` | 原生控件 |

配合 `comctl32.dll` v6 清单（视觉样式）与 DPI 感知声明，界面可达到现代 Windows 程序观感，且**无需任何第三方 UI 框架**。

### 4.6 MinGW-w64 工具链适配性（关键，逐项评估）

本地已配置 MinGW 的 `g++` 环境，因此需要逐项确认各能力在 MinGW 下是否可用：

| 能力 | 依赖 | MinGW 支持 | 备注 |
| --- | --- | --- | --- |
| Win32 基础 API | `kernel32` / `user32` / `gdi32` | ✅ 完善 | 直接可用 |
| 注册表 | `advapi32` | ✅ 完善 | `Reg*` 系列 API |
| 公共控件 | `comctl32` | ✅ 完善 | ListView / TreeView / ProgressBar |
| Shell 集成 | `shell32` / `shlwapi` | ✅ 完善 | 路径、快捷方式、回收站 |
| 服务管理（SCM） | `advapi32` | ✅ 完善 | `OpenSCManager` / `EnumServicesStatusEx` / `DeleteService` |
| MSI 枚举 | `msi` | ✅ 可用 | `MsiEnumProductsExW`；如头文件缺失可改为动态加载 `msi.dll` |
| 系统还原点 | `srclient.dll` | ✅ 运行时动态加载 | `LoadLibraryW` + `GetProcAddress`，不产生链接依赖 |
| 计划任务 | `taskschd`（COM） | ⚠️ 需手工 GUID | 备选：直接操作 `%SystemRoot%\System32\Tasks` 文件 |
| WMI | COM + `wbemidl` | ⚠️ 支持有限 | **设计上尽量不用 WMI**，改用 SCM / 注册表 / 文件系统 |
| COM 基础 | `ole32` / `oleaut32` | ⚠️ 可用但繁琐 | MinGW 无 `comdef.h`，`__uuidof` 支持不完整，需显式使用 `IID_*` / `CLSID_*` |
| 资源编译 | `windres` | ✅ 完善 | `.rc` → `.res` → 链接 |
| 静态链接 | `-static` 系列 | ✅ 完善 | 可消除 MinGW 运行时 DLL |
| 代码签名 | `signtool`（外部） | ✅ 与编译器无关 | 签名在编译产物上进行 |

**关键设计结论**：
1. **优先使用直接 Win32 API，尽量不用 COM / WMI**。服务用 SCM、启动项用注册表、还原点用 `srclient`、计划任务用文件或 Task Scheduler COM（后期）。
2. **GUID 一律显式声明**，不依赖编译器扩展。
3. **第三方库只选头文件或可源码编译的**，避免引入 `.dll` / `.lib` 二进制依赖。

### 4.7 技术可行性小结

| 能力 | 可行性 | 备注 |
| --- | --- | --- |
| 全机软件枚举 | ✅ 高 | 注册表 + UWP + MSI 三源合并 |
| 定位安装目录 | ✅ 高 | 依赖 `InstallLocation` |
| 直接删除程序本体 | ✅ 高 | 标准文件 API |
| 清理用户数据 | ⚠️ 中 | 依赖名称 / 厂商匹配，需规则库支持 |
| 清理注册表残留 | ⚠️ 中 | 卸载键可靠，其余靠匹配 |
| 清理服务 / 计划任务 | ✅ 中高 | SCM + 文件 / COM |
| 纯 Win32 原生界面 | ✅ 高 | 公共控件完全覆盖需求 |
| **单文件 exe 打包** | ✅ **高** | 静态链接 + 源码集成第三方库 |
| 绝对"零残留" | ❌ 不可达 | 所有同类工具都无法保证 |

## 5. 关键难点与风险

### 5.1 技术难点

| 编号 | 难点 | 影响 | 应对思路 |
| --- | --- | --- | --- |
| D1 | 痕迹无法穷举 | 清理不彻底 或 误删 | 规则库 + 多重匹配 + 预览确认 |
| D2 | 共享组件误删 | 破坏其他软件（如 VC++ 运行库、.NET、DirectX） | 内置保护白名单，识别"被多个软件引用"的目录 |
| D3 | 系统文件误删 | 系统不稳定 / 无法启动 | 系统目录硬保护 + 严格路径校验 |
| D4 | 文件被占用 | 删不掉 | 停止相关进程 / 服务；`MoveFileEx` 延迟到重启删除 |
| D5 | 权限不足 | 部分系统级项无法删除 | 提权运行 + 明确提示失败项 |
| D6 | 判断"哪些残留属于它" | 误伤 / 漏删 | 规则库 + 厂商 / 产品名前缀匹配 + 时间线分析 |
| D7 | MinGW 下 COM / WMI 支持不完整 | 部分功能实现受阻 | 设计上回避 WMI；COM 显式声明 GUID；备选动态加载 |
| D8 | 静态链接后体积膨胀 | 分发体积变大 | 编译期裁剪、`-Os`、`-s` strip、避免引入重型库 |

### 5.2 风险等级评估

| 风险 | 等级 | 说明 |
| --- | --- | --- |
| 误删导致系统或软件损坏 | 🔴 高 | **头号风险**，必须靠备份 / 还原点兜底 |
| 残留清理不彻底 | 🟡 中 | 影响体验，可接受（同类工具通病） |
| 杀毒软件误报 | 🟡 中 | 需要代码签名 + 白名单申诉（强制卸载类工具尤其敏感） |
| SmartScreen / 用户不信任 | 🟡 中 | 需要可信签名证书 |
| MinGW 工具链兼容问题 | 🟡 中 | 阶段 0 提前验证，锁定可用 GCC 版本 |
| 部分软件无法强制卸载 | 🟢 低 | 明确提示，可回退到官方卸载 |

## 6. 合规与安全声明（重要）

1. **定位声明**：本工具的强制卸载能力，用于帮助用户清理**自己设备上**、由**卸载程序收费 / 广告阻碍卸载**的软件；**不提供**任何破解、绕过授权、规避正版验证的能力。
2. **免责声明**：卸载属用户主动发起的系统变更操作，工具需在界面中明确提示风险，并要求用户确认；因误删造成的损失由用户自担（同时通过还原点尽可能降低风险）。
3. **数据保护**：工具不采集、不上传用户软件清单与文件内容，核心功能纯本地运行。
4. **第三方条款**：强制卸载可能触及部分软件的最终用户协议（EULA），产品需在用户协议中作出风险提示。

## 7. 竞品分析

| 产品 | 卸载模式 | 强制卸载 | 残留清理 | 单文件绿色 | 备注 |
| --- | --- | --- | --- | --- | --- |
| **Geek Uninstaller** | 官方卸载 + 残留扫描 | ❌ | 中 | ✅ | 轻量、原生，但不绕过卸载程序 |
| **Revo Uninstaller** | 官方卸载 + 追踪 | 部分 | 高 | ❌ 需安装 | 追踪能力强，专业版收费 |
