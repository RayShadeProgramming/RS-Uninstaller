## 1. 项目概述

### 1.1 项目名称
**RS-Uninstaller**

### 1.2 一句话定位
一款**仅面向 Windows 客户端**的深度强制卸载工具：自动识别本机已安装的全部软件，在**不启动软件自带卸载程序**的前提下，直接定位其安装目录、用户数据与注册表项，一次性彻底清除。

### 1.3 目标用户
- 反感"卸载要付费 / 弹广告 / 引导下载其他软件"的普通用户；
- 需要批量、干净卸载的装机 / 运维 / 电脑维护人员；
- 对系统残留、开机启动项敏感的性能爱好者。

### 1.4 与主流工具的差异

| 维度 | Geek Uninstaller | RS-Uninstaller |
| --- | --- | --- |
| 卸载方式 | 先调用**官方卸载程序**，成功后再扫描残留 | **不调用**官方卸载程序，直接清理 |
| 面对"收费卸载" | 无解，仍会被卸载程序拦截 | 直接跳过卸载程序，规避收费 / 广告关卡 |
| 残留清理 | 事后启发式扫描 | 事前构建"清理清单"后整体清除 |
| 安全模型 | 依赖官方卸载，风险天然较低 | 风险高，**必须**内置还原点 + 备份兜底 |
| 产品调性 | 通用卸载器 | 强制卸载 / 深度清理 |

> 结论：本项目与 Geek 的**根本区别**在于"跳过官方卸载程序"，这既是卖点，也是最大风险来源。技术方案必须围绕"如何安全地跳过"设计。

| 编号 | 约束 | 说明 |

## 3. 技术路线说明

### 3.1 从 C++ 调整为 Python 的原因

| 维度 | C++ 方案（原） | Python 方案（现） |
| --- | --- | --- |
| 开发效率 | 低（内存 / 字符串 / COM 处理繁琐） | **高**（标准库直接覆盖） |
| 界面 | 纯 Win32 手写消息循环 | **tkinter / ttk**，几十行即可搭出界面 |
| 系统 API | 直接调用 Win32 | `winreg` 直连注册表 + `ctypes` 调 Win32 |
| 单文件 exe | 静态链接，1~3 MB | PyInstaller 打包，约 10~20 MB |
| 目标机依赖 | 无 | **无**（解释器打包进 exe） |
| 调试迭代 | 编译等待 | 改完即运行 |

**结论**：Python 在保持"单文件、目标机零依赖"的前提下，大幅降低开发与迭代成本；代价是产物体积变大、首次启动略慢。对工具类软件这个取舍是划算的。

### 3.2 单文件 exe 的实现路径

```
Python 源码（仅标准库）
  ├─ tkinter / ttk            界面
  ├─ winreg / ctypes          系统交互
  └─ 图标资源 res/icon.ico
        ↓  PyInstaller --onefile --windowed --uac-admin
   单个 RS-Uninstaller.exe（内含 Python 运行时）
```

关键点：
- 不引入任何第三方运行时包，依赖面与体积最小；
- `--uac-admin` 嵌入管理员权限清单，启动即提权；
- 图标通过 `--add-data` 打包，代码用 `sys._MEIPASS` 兼容定位。

## 4. 技术可行性分析

### 4.1 软件信息来源（可行 ✅）

| 来源 | 位置 / 接口 | 覆盖范围 |
| --- | --- | --- |
| 64 位机器级注册表 | `HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Uninstall` | 常规 64 位软件 |
| 32 位机器级注册表 | 同路径 + `KEY_WOW64_32KEY` 视图 | 32 位软件 |
| 当前用户级注册表 | `HKCU\SOFTWARE\...\Uninstall` | 仅当前用户安装 |
| MSI 产品库 | Uninstall 项中的 `WindowsInstaller` 标识 | MSI 安装包软件 |
| 目录启发式扫描 | `Program Files` 等 | 绿色 / 便携软件（补充） |

**关键字段**：`DisplayName`、`DisplayVersion`、`Publisher`、`InstallLocation`、`UninstallString`、`EstimatedSize`、`InstallDate`、`WindowsInstaller`、`SystemComponent`、`ParentKeyName`、`ReleaseType`。

**过滤规则**：排除 `SystemComponent=1`、含 `ParentKeyName`（补丁 / 子组件）、`ReleaseType` 为 Update/Hotfix/Security Update 的条目。

### 4.2 痕迹追踪可行性（部分可行 ⚠️）

| 可靠度 | 手段 | 说明 |
| --- | --- | --- |
| 高 | `InstallLocation` 递归 | 注册表直接给出的安装目录 |
| 高 | 卸载键关联的注册表子键 | 厂商 / 产品名对应项 |
| 中 | 按名称 / 厂商匹配 | AppData、ProgramData、开始菜单 |
| 中 | 服务反查 | 通过服务 `ImagePath` 反查程序目录 |
| 中 | 快捷方式反查 | `.lnk` 指向的路径 |
| 低 | COM / 文件关联 / Shell 扩展 | 需解析 CLSID 与程序路径对应关系 |

> **关键结论**：无法 100% 穷举全部痕迹（同类工具的共同局限）。产品只能承诺"在规则与追踪能力范围内尽量干净，且提供预览与回滚"，因此必须走"扫描 → 预览 → 备份 → 清理"的安全流程。

### 4.3 权限与提权（可行 ✅）

- 启动时通过 `ShellExecuteW(..., "runas", ...)` 自我提权，配合 PyInstaller `--uac-admin`；
- 注册表访问区分 `KEY_WOW64_64KEY` / `KEY_WOW64_32KEY`；
- 系统还原点、服务删除均需管理员权限。

### 4.4 安全兜底可行性（可行 ✅）

| 兜底手段 | 实现方式 |
| --- | --- |
| 系统还原点 | `ctypes` 动态加载 `srclient.dll`，调用 `SRSetRestorePointW` |
| 注册表备份 | 递归导出为 JSON 快照（键、值、类型、数据），可原样回灌 |
| 文件备份 | 删除前移动到隔离区，保留原目录结构 |
| 还原 | 按 journal 逐项还原；目录已存在时合并缺失文件 |
| 白名单保护 | 系统盘根、Windows、Program Files、ProgramData、用户目录等硬保护 |

### 4.5 tkinter 界面可行性（可行 ✅）

| 需求 | tkinter 实现 |
| --- | --- |
| 软件列表 | `ttk.Treeview` 多列、排序、滚动 |
| 搜索过滤 | `ttk.Entry` + `StringVar` |
| 清理清单勾选 | 自定义 `CheckTreeview`（首列 ☑ / ☐） |
| 进度 | `ttk.Progressbar` |
| 风险确认 | `messagebox.askyesno`（默认选"否"） |
| 原生外观 | ttk `vista` 主题 |

### 4.6 Python 标准库覆盖度（关键，逐项评估）

| 能力 | 依赖 | 可行性 | 备注 |
| --- | --- | --- | --- |
| 注册表枚举 / 读写 / 递归删除 | `winreg` | ✅ | 支持 32 / 64 位视图 |
| 文件遍历 / 移动 / 删除 | `os` / `shutil` | ✅ | 跨卷自动复制后删除 |
| 服务枚举 | `ctypes` + advapi32 | ✅ | `EnumServicesStatusExW` |
| 服务停止 / 删除 | `ctypes` + advapi32 | ✅ | `ControlService` / `DeleteService` |
| 系统还原点 | `ctypes` + srclient.dll | ✅ | 不可用时降级为备份 |
| 管理员检测 / 提权 | `ctypes` + shell32 | ✅ | `IsUserAnAdmin` / `ShellExecuteW` |
| 后台执行 + 进度 | `threading` / `queue` | ✅ | 避免界面卡死 |
| 打包单文件 | PyInstaller | ✅ | `--onefile --uac-admin` |

### 4.7 技术可行性小结

| 能力 | 可行性 | 备注 |
| --- | --- | --- |
| 全机软件枚举 | ✅ 高 | 注册表四路来源合并 |
| 定位安装目录 | ✅ 高 | `InstallLocation` |
| 直接删除程序本体 | ✅ 高 | `shutil` |
| 清理用户数据 | ⚠️ 中 | 依赖名称 / 厂商匹配 |
| 清理注册表残留 | ⚠️ 中 | 卸载键可靠，其余靠匹配 |
| 服务清理 | ✅ 中高 | SCM API |
| 单文件 exe 打包 | ✅ 高 | PyInstaller |
| 绝对"零残留" | ❌ 不可达 | 同类工具均无法保证 |

## 5. 关键难点与风险

### 5.1 技术难点

| 编号 | 难点 | 影响 | 应对 |
| --- | --- | --- | --- |
| D1 | 痕迹无法穷举 | 清理不彻底或误删 | 规则 + 多重匹配 + 预览确认 |
| D2 | 共享组件误删 | 破坏其他软件 | 保护白名单 |
| D3 | 系统文件误删 | 系统不稳定 | 系统目录硬保护 |
| D4 | 文件被占用 | 删不掉 | 记录失败项，提示关闭程序 |
| D5 | 权限不足 | 系统级项无法删除 | 提权运行 + 如实报告 |
| D6 | 误判残留归属 | 误伤 / 漏删 | 保守匹配策略，宁漏勿错 |

### 5.2 风险等级评估

| 风险 | 等级 | 说明 |
| --- | --- | --- |
| 误删导致系统或软件损坏 | 🔴 高 | 头号风险，靠备份 / 还原点兜底 |
| 残留清理不彻底 | 🟡 中 | 影响体验，同类工具通病 |
| 杀毒软件误报 | 🟡 中 | 强制卸载类工具敏感，需签名与白名单 |
| 单文件体积偏大 | 🟢 低 | 约 10~20 MB，可接受 |
| 部分软件无法强制卸载 | 🟢 低 | 明确提示并记录失败项 |

## 6. 合规与安全声明

1. **定位**：仅用于清理用户自己设备上、因收费 / 广告阻碍卸载的软件；**不提供**破解、绕过授权、规避正版验证的能力。
2. **免责**：卸载是用户主动发起的系统变更，界面需明确提示风险并要求确认；误删损失由用户自担（通过还原点尽量降低）。
3. **数据保护**：不采集、不上传软件清单与文件内容。
4. **第三方条款**：强制卸载可能触及部分软件 EULA，需在用户协议中提示。

## 7. 竞品分析

| 产品 | 卸载模式 | 强制卸载 | 残留清理 | 单文件绿色 | 备注 |
| --- | --- | --- | --- | --- | --- |
| **Geek Uninstaller** | 官方卸载 + 残留扫描 | ❌ | 中 | ✅ | 轻量原生，但不绕过卸载程序 |
| **Revo Uninstaller** | 官方卸载 + 追踪 | 部分 | 高 | ❌ | 追踪强，专业版收费 |
| **IObit Uninstaller** | 官方卸载 + 强制卸载 | ✅ | 高 | ❌ | 功能全，有推广 |
| **Total Uninstall** | 安装前追踪 | ✅ | 极高 | ❌ | 需安装前监控 |
| **RS-Uninstaller** | **直接清理** | ✅ | 高（规则驱动） | ✅ | 主打跳过卸载程序 + 安全回滚 |

**差异化机会**：强制卸载能力多藏在收费版，且多数需安装、带服务组件；本项目可把"安全的强制卸载 + 完整回滚 + 单文件绿色"做成核心能力。

## 8. 结论

| 评估项 | 结论 |
| --- | --- |
| 技术可行性 | ✅ 可行。注册表与 Win32 API 成熟，同类产品验证过路线 |
| 工程可行性 | ✅ 可行。Python 标准库即可覆盖全部需求，单文件打包成熟 |
| 开发效率 | ✅ 高。无编译环节，迭代快 |
| 主要风险 | ⚠️ 误删风险高，必须依赖还原点 / 备份 / 白名单 |
| 功能边界 | ⚠️ 无法承诺零残留，需如实告知 |
| 合规性 | ✅ 可做，需明确不破解定位并附免责声明 |
| **总体结论** | ✅ **项目可行**。成败关键不在"删得狠"，而在"清单算得准 + 出事能还原" |

**建议**：先跑通只读流程（扫描 + 预览 + 备份，不删除），确认清单准确率后再开放删除能力。
